# 后端构建流程说明

> 说明：该文档根据现有前端接口与业务模块，整理出一套从零搭建后端的步骤。目标是从后端根目录开始，按工程化顺序逐步完成基础设施、数据库、认证、业务模块、缓存与测试，最终对接前端 `src/api/*` 中的接口。

## 一、建议从哪个目录开始

建议从后端工程根目录开始，不要直接从某个业务模块写代码，先按以下顺序搭建：

```text
smart-teaching-backend/
├─ pom.xml
├─ src/main/java/com/smartteaching/
├─ src/main/resources/
├─ src/test/java/com/smartteaching/
├─ sql/
└─ README.md
```

优先启动顺序：

1. `pom.xml`：定义依赖（Spring Boot、MyBatis、MySQL 驱动、Redis、JWT、分页插件、Swagger）
2. `application.yml`：配置数据库、Redis、JWT、文件上传、日志
3. `SmartTeachingApplication.java`：启动 Spring Boot 工程
4. `config/`：先完成安全、跨域、Redis、异常处理
5. `common/`：统一返回、异常、工具类
6. `entity/` + `mapper/`：先落地数据库表结构
7. `service/`：实现核心业务逻辑
8. `controller/`：暴露 REST 接口
9. 测试与联调

- 配置数据库连接、Redis、日志、JWT
- 启动 `Spring Boot` 应用

### 第 2 步：建立基础设施层

需要实现：

- `common/result/Result.java`
- `common/result/PageResult.java`

### 第 3 步：配置安全和鉴权

需要实现：

- `config/SecurityConfig.java`
- `config/JwtAuthenticationFilter.java`

- 允许前端跨域访问

这里是后端最先要打通的部分，因为前端登录、用户权限、页面访问都依赖它。

## 三、构建顺序建议（最实用版）

如果团队要按最稳妥的顺序推进，建议如下：

1. `common` + `config` + `security`
2. `entity` + `mapper`
3. `auth` + `user` + `org`
4. `course` + `selection`
5. `score` + `attendance`
6. `notice` + `qa` + `ai`
7. `evaluation` + `warning` + `dashboard`
8. 缓存 + 定时任务 + 测试

这顺序是最符合当前前端接口设计的；基本先保证“登录/权限/组织/课程/选课”能跑通，再逐步扩展到统计、通知和 AI 模块。

---

## 四、注意事项

1. 所有接口返回必须和前端统一：`{ code, data, msg }`
2. 所有分页接口统一使用 `pages` 和 `size`
3. `401` 代表未登录或 Token 过期
4. `403` 代表无权限访问
5. `Excel` 导入导出要用统一工具类
6. Redis 不要存放全量业务表数据，只存放高频、可重建、可失效的数据

---

## 五、总结

从前端现有结构看，后端最适合构建成一个典型的 `Spring Boot + MyBatis + MySQL + Redis + JWT` 的企业管理系统后端，职责划分明确。

最合理的开发顺序是：

- 先基础层
- 再认证与用户
- 再组织与课程
- 再选课、成绩、考勤
- 最后补齐公告、问答、AI 和统计分析模块

这样可以最快实现前端接口对接，并保证后续维护成本最低。
