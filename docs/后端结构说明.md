# 智慧教学平台后端结构说明

> 说明：基于现有前端 `src/api/*.js` 以及接口文档推断，后端适合采用 `Java + Spring Boot + MyBatis/MyBatis-Plus + MySQL + Redis + JWT` 的分层架构。前端统一使用 `axios`，所有接口均遵循 `{ code, data, msg }` 返回格式，因此后端接口设计应与之保持一致。

## 二、各层职责说明

### 1. `common` 层：共用基础能力

- `Result.java`：定义统一返回结构 `{ code, data, msg }`
- `BizException.java`：自定义业务异常
- `GlobalExceptionHandler.java`：统一拦截 `400/401/403/404/500` 等异常
- `JwtUtils.java`：JWT 生成、校验、解析
- `ExcelUtils.java`：批量导入/导出 Excel
- `DateUtils.java`：处理时间格式、周次计算、课程时间计算

### 2. `config` 层：系统配置

- `SecurityConfig.java`：配置认证、授权、放行路径、角色权限
- `JwtAuthenticationFilter.java`：在每次请求中解析 Token
- `RedisConfig.java`：Redis 连接池、序列化配置
- `WebMvcConfig.java`：跨域、统一参数解析、静态资源映射

### 3. `entity` 层：数据库实体

- 与 MySQL 表一一对应，主要包括：
  - 用户与角色
  - 学院/专业/班级组织结构
  - 课程与排课
  - 选课配置与选课记录
  - 成绩与考勤
  - 公告、问答、AI 对话、评价、预警

### 4. `mapper` 层：持久化接口

- 负责数据库查询、插入、更新、删除
- 典型文件：
  - `UserMapper.java`：用户登录、权限查询
  - `OrgMapper.java`：组织结构树、层级查询
  - `CourseMapper.java`：课程列表和排课查询
  - `SelectionMapper.java`：选课记录、名额校验
  - `DashboardMapper.java`：数据统计

### 5. `service` 层：核心业务逻辑

- 负责校验、事务、组合处理和缓存调用
- 典型职责：
  - `AuthServiceImpl`：登录、登出、校验 Token、修改密码
  - `UserServiceImpl`：增删改查用户，权限控制
  - `OrgServiceImpl`：组织树结构维护、级联删除校验
  - `CourseServiceImpl`：创建课程、冲突校验、批量排课
  - `SelectionServiceImpl`：选课时间控制、名额检查、退课逻辑
  - `ScoreServiceImpl`：录入/导入/统计成绩
  - `AttendanceServiceImpl`：签到码生成、签到校验、统计
  - `AiServiceImpl`：AI 助教调用和问答历史管理

### 6. `controller` 层：REST API 对外接口

- 对应前端各个 `src/api/*.js` 模块
- 例如：
  - `AuthController`：`/auth/login`、`/auth/userInfo`
  - `CourseController`：`/course/list`、`/course/schedule/list`
  - `SelectionController`：`/selection/select/{courseId}`
  - `AttendanceController`：`/attendance/generate`、`/attendance/submit`
  - `DashboardController`：`/dashboard/admin`、`/dashboard/student`

### 7. `scheduler` 层：定时任务

- 定期扫描课程提醒、预警信息、签到超时处理
- 如：
  - `AttendanceReminderTask.java`：考勤提醒
  - `WarningScanTask.java`：预警扫描

### 8. `integration` 层：外部系统适配

- `AiClient.java`：接入 AI 大模型回答
- `EmailClient.java`：邮件通知
- `OcrClient.java`：可选文件识别/证件检测

## 四、建议的后端职责边界

1. `controller` 只负责接收参数、调用 service、返回统一结果。
2. `service` 负责业务校验和事务处理。
3. `mapper` 只负责持久化操作，不做业务判断。
4. `common` 和 `config` 负责全局基础设施。
5. 计算密集、缓存型和外部调用类逻辑尽量收敛到 `service` / `integration`。

## 五、后端工程落地建议

如果团队要从零开始搭建，优先顺序为：

1. `pom.xml` + `application.yml` + `database` 连接配置
2. `common` 基础工具与统一返回
3. `config` 安全配置 + JWT
4. `entity` + `mapper` + `MyBatis XML`
5. `auth` / `user` / `org` 三大基础模块
6. `course` / `selection` 核心业务模块
7. `score` / `attendance` / `notice` / `qa` / `ai`
8. `dashboard`、`warning`、`evaluation` 汇总统计
9. 定时任务、缓存与消息队列
10. 单元测试和接口测试

这套分层方式最符合当前前端接口的业务边界，也便于后续扩展和维护。
