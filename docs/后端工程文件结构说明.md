# 后端工程文件结构说明（Spring Cloud 微服务版）

> 定位：帮你理清 `smart-teaching-cloud` 的模块与文件结构。单体里已有的 controller / service / mapper / entity 等**平移文件只做一句话说明**，重点讲**微服务化新增的文件**和**关键配置**。

## 一、模块总览

```
smart-teaching-cloud (pom 聚合，11 个模块)
├── common            公共模块：工具 / 异常 / 常量 / 公共配置 / 公共实体与 Mapper
├── api               微服务新增：Feign 接口契约 + 内部调用 DTO（跨服务）
├── gateway-service   微服务新增：API 网关（8080）
├── uaa-service            8081  认证 / 用户 / 组织
├── course-service         8082  课程 / 排课
├── selection-score-service 8083 选课 / 成绩
├── attendance-service     8084  考勤签到
├── warning-service        8085  学业预警
├── ai-service             8086  AI 助教（Ollama）
├── analysis-service       8087  数据仪表盘
└── teaching-service       8088  作业 / 通知 / 评价 / 答疑
```

依赖关系：`common` ← `api`（api 依赖 common）← 各业务服务（都依赖 common + api）；`gateway-service` 只依赖 common（路由无需业务代码）。根 `pom.xml` 用 Spring Cloud / Alibaba BOM 统一管理版本。

## 二、三个"微服务专用"模块（重点）

### 1. common —— 单体公共代码的收敛地

| 包 | 文件 | 说明 |
|---|---|---|
| `common.result` | `Result` / `PageResult` | 统一返回体（平移，全服务共用） |
| `common.exception` | `BaseException` / `GlobalExceptionHandler` / `PasswordErrorException` 等 | 统一异常体系（平移，收敛到公共模块） |
| `common.constant` | `UserRoleEnum` / `AttendanceStatus` / `ErrorCode` / `ResultCode` 等 | 常量枚举（平移收敛） |
| `common.utils` | `JwtUtil` / `RedisUtils` / `PasswordUtils` / `SecurityUtils` / `DateUtils` / `WeekUtil` | 工具类（平移收敛，JWT 密钥全服务一致） |
| `common.entity` | `User` / `Course` / `CourseSchedule` / `BaseEntity` | **公共实体**：多服务都要操作的表（如用户表几乎所有服务都要查） |
| `common.mapper` | `UserMapper` | **公共 Mapper**：随公共实体放入 common |
| `common.service` | `CustomUserDetailsService` | 认证用户加载（各服务 Security 共用） |
| `common.filter` | **`InternalApiCheckFilter`（微服务新增）** | 内部接口防护过滤器，见下文 §四-4 |
| `common.config` | `MybatisPlusConfig` / `RedisConfig` / `WebMvcConfig` | 公共配置，见 §四-5 |

### 2. api —— 微服务之间的"电话本"（Feign 契约）

这是纯微服务新增模块，不跑业务，只定义**跨服务调用接口**。

| 文件 | 作用 |
|---|---|
| `client/UserFeignClient` | 指向 uaa-service 内部接口：按 id / 用户名查用户（其他服务要显示"授课教师姓名、学生姓名"时用） |
| `client/CourseFeignClient` | 指向 course-service：按 id 查课程、按条件查课程列表 |
| `client/SelectionFeignClient` | 指向 selection-score-service：查询选课信息（如考试/评分相关） |
| `client/WarningFeignClient` | 指向 warning-service：推送预警（考勤、成绩模块联动时用） |
| `config/InternalFeignInterceptor` | **关键**：所有 Feign 请求自动携带 `X-Internal-Call: smart-teaching-cloud` 头，让服务端认出"这是内部调用" |
| `dto/CourseInfoVO` / `UserInfoVO` / `TruantWarningDTO` | 跨服务传输的 DTO（与各服务私有 DTO 区分开） |

> 注意区分：`api/dto` 是**跨服务**传参；每个业务服务里的 `common/dto` `common/vo` 是**自己模块内部**的入参/出参。

### 3. gateway-service —— 统一入口（仅 3 个类 + 1 个配置）

| 文件 | 作用 |
|---|---|
| `GatewayApplication` | 启动类，`@EnableDiscoveryClient` 注册进 Nacos |
| `config/GatewayRouteConfig` | **核心路由**：用 Java DSL 声明"URL 前缀 → 服务名"，`lb://` 走 Nacos 负载均衡 |
| `config/CorsConfig` | WebFlux 响应式统一跨域（前端跨域只在网关解决，各服务不必再配） |
| `application.yml` | 只配端口 8080 + Nacos 注册地址，**无数据源**（网关不碰数据库） |

路由对照（前端 / Nginx 无需改路径，全部经网关转发）：

```
/api/auth/**, /api/user/**, /api/org/**  → lb://uaa-service
/api/course/**, /api/schedule/**        → lb://course-service
/api/selection/**, /api/score/**        → lb://selection-score-service
/api/attendance/**                      → lb://attendance-service
/api/warning/**                         → lb://warning-service
/api/ai/**, /api/ollama/**              → lb://ai-service
/api/dashboard/**                       → lb://analysis-service
/api/notice/**, /api/qa/**, /api/evaluation/**, /api/homework/** → lb://teaching-service
/files/**                               → lb://uaa-service（静态文件统一由 uaa 托管）
```

## 三、8 个业务服务：结构完全同构

每个业务服务内部包结构一致（以下以 course-service 为例，其余服务替换业务名即可）：

```
course-service/
├── CourseApplication.java            启动类（@EnableDiscoveryClient + @EnableFeignClients）
├── config/                           JwtAuthenticationFilter / SecurityConfig / SwaggerConfig
├── controller/course/                CourseController        对外接口（经网关访问）
├── controller/internal/              CourseInternalController 服务间接口（仅 Feign 调）
├── controller/schedule/              ScheduleController
├── service/course/ ...               CourseService / CourseServiceImpl
├── service/service/ ...              ScheduleService / ScheduleServiceImpl
├── mapper/                           CourseMapper / ScheduleMapper
├── entity/course/ ...                Course / CourseSchedule（只放本模块表）
├── common/dto/ common/vo/ ...        模块私有入参 / 出参
└── resources/application.yml         见 §四-6
```

**各服务业务清单**（表名按实体推断）：

| 服务 | 端口 | 业务 | 涉及表 |
|---|---|---|---|
| uaa-service | 8081 | 登录 / 登出 / 验证码、用户增删改查、组织架构 | user、role、user_role、college、major、class_info |
| course-service | 8082 | 课程管理、排课管理（三重冲突校验） | course、course_schedule |
| selection-score-service | 8083 | 选课（开放设置 / 选课退课 / 智能推荐）、成绩录入 / 统计 / 异常筛查 | selection_config、selection_record、score |
| attendance-service | 8084 | 九宫格签到会话、考勤记录、定时结束会话并落实旷课 | attendance_session、attendance_record |
| warning-service | 8085 | 学业预警生成 / 查询 / 导出 | warning |
| ai-service | 8086 | AI 助教（知识点答疑 / 评语生成 / 学业分析） | ai_session、ai_message、ai_daily_usage |
| analysis-service | 8087 | 三角色仪表盘统计（数据经 Feign 从各服务聚合） | dashboard_stat |
| teaching-service | 8088 | 作业发布 / 提交 / 批改、通知公告、课程评价、答疑社区 | homework、homework_submission、notice、notice_read_record、course_evaluation、question、reply |

**定时任务（新增）**：`attendance-service/config/AttendanceScheduleTask.java` —— 每分钟 `@Scheduled` 结束超时签到会话，将缺勤落实为旷课并联动生成预警（微服务下"定时 + 跨服务联动"的体现）。

**AI 服务新增配置**：`ai-service/config/OllamaConfig.java`（`@ConfigurationProperties` 读 ollama 配置，对 0.0.0.0 / 缺协议等环境变量做规整）、`WebClientConfig`（异步 HTTP 调 Ollama，不阻塞主流程）。

## 四、关键配置（重点）

### 4-1 根 pom.xml —— 版本与依赖统一

```
spring-cloud.version = 2025.1.0
spring-cloud-alibaba.version = 2025.1.0.0
dependencyManagement 引入：spring-cloud-dependencies + spring-cloud-alibaba-dependencies
同时锁定内部模块 smart-teaching-common / smart-teaching-api 与各第三方版本
```

### 4-2 每个业务服务 application.yml —— 微服务化核心配置

```yaml
spring:
  application:
    name: course-service          # 服务名 = Nacos 注册名 = Feign 调用名（必须唯一）
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8848   # 注册到 Nacos
  datasource: ...                  # 共享同一 smart_teaching 库（多服务共享单库）
  data.redis: ...                  # 共享同一 Redis（缓存 / 登出黑名单 / AI 限额）
server:
  port: 8082                       # 每服务独立端口
jwt:
  secret: abcdefghijklmnopqrstuvwxyz1234567890   # 所有服务同一密钥，跨服务校验一致
  expiration / header / token-prefix
file:
  upload-path: .../smart-teaching-cloud/uploads  # 上传目录统一（WebMvcConfig 映射 /files/**）
```

### 4-3 gateway application.yml —— 最简，无数据源

```yaml
server.port: 8080
spring.application.name: gateway-service
spring.cloud.nacos.discovery.server-addr: 127.0.0.1:8848
```

### 4-4 内部接口防护（微服务新增的安全机制）

- **服务端**：`common/filter/InternalApiCheckFilter` —— 所有服务都会加载（common 被引用），拦截 `/api/internal/**`，只有带 `X-Internal-Call: smart-teaching-cloud` 头的请求放行，否则 403。
- **客户端**：`api/config/InternalFeignInterceptor` —— Feign 每次调用自动补这个头。
- **SecurityConfig** 相应放行 `/api/internal/**`（见下）。

### 4-5 公共配置类

| 配置 | 作用 |
|---|---|
| `MybatisPlusConfig` | 分页插件（max 100）、乐观锁、防全表更新拦截、`@MapperScan("com.smartteaching.mapper")` 只扫公共 Mapper、createTime/updateTime 自动填充 |
| `RedisConfig` | 自定义 Jackson 序列化防乱码，提供 RedisTemplate / StringRedisTemplate |
| `WebMvcConfig` | 上传目录统一指向 `smart-teaching-cloud/uploads`，`/files/**` 全局可访问；LocalDateTime 序列化格式 |

### 4-6 每个服务 SecurityConfig —— 与单体相比只多一处

单体逻辑平移（无状态、禁 CSRF、BCrypt、JWT 过滤器注册、admin 路径 ADMIN 角色），**新增放行**：

```java
.requestMatchers("/api/internal/**").permitAll()   // 内部接口放行（由 InternalApiCheckFilter 校验标识）
```

`JwtAuthenticationFilter` 也是单体平移：每服务独立解析 JWT → 校验 Redis 黑名单 → 设置 SecurityContext。这就是"每个服务都有一份 config"的原因——微服务独立部署，鉴权必须自带，属于必要重复而非失误。

## 五、平移 vs 新增 对照表

| 内容 | 来源 | 说明 |
|---|---|---|
| controller / service / mapper / entity / DTO / VO | 单体平移 | 业务逻辑基本不变，按模块搬入各自服务，包结构加了业务名分组（如 `controller/course`） |
| `Result` / `PageResult` / 异常 / 工具 / 常量 | 单体平移 + 收敛 | 从单体各包集中到 common，去重 |
| `SecurityConfig` / `JwtAuthenticationFilter` / `SwaggerConfig` | 单体平移 + 微调 | 每个服务保留一份（独立部署必需），Security 仅增加 internal 放行 |
| **gateway-service 全部** | **微服务新增** | 路由 + CORS + 启动注册 |
| **api 模块全部** | **微服务新增** | Feign 接口 + 内部 DTO + 拦截器 |
| **InternalApiCheckFilter** | **微服务新增** | 内部接口防外部直连 |
| **各服务 controller/internal/** | **微服务新增** | 服务间 Feign 落地接口 |
| **AttendanceScheduleTask** | **微服务新增** | 定时结束签到会话、联动预警 |
| **OllamaConfig / WebClientConfig** | **微服务新增** | AI 服务接入本地大模型 |
| **application.yml 的 nacos / jwt / datasource 段** | **微服务新增/改造** | 注册发现、统一密钥、共享数据源 |
| `@EnableDiscoveryClient` / `@EnableFeignClients` 注解 | **微服务新增** | 注册中心 / 声明式调用开关 |

## 六、一次请求的完整链路（帮你串起来）

```
浏览器 → 前端(5173/8888) → /api/auth/login → Gateway(8080) 按前缀路由 → uaa-service 登录返回 JWT
之后请求都带 Authorization: Bearer xxx
→ Gateway → 对应服务 → Security/JwtFilter 校验 → controller 处理业务
→ 需要别的服务的数据（如成绩列表要课程名）→ 本服务 @Autowired FeignClient
   → InternalFeignInterceptor 自动带 X-Internal-Call 头 → 对方 /api/internal/** 放行 → 返回
   （外部用户即使猜到 internal 路径也进不来，网关不发往 internal，且缺标识被 Filter 拦）
```
