# 前端接口需求文档（后端开发必须遵守版）

> 作用：本文档只描述前端真实需要的接口和字段，不包含“后端自定义命名自由发挥”。
>
> 目标：让后端开发者只要按这里的接口和字段来写，就不会出现“前端请求参数不对、字段不一致、列表没显示”的问题。

---

## 一、全局统一约定

### 1.1 统一返回结构

前端统一使用 `axios`，并在 [nginx-1.31.3/smart-teaching-web/src/utils/request.js](nginx-1.31.3/smart-teaching-web/src/utils/request.js) 中统一处理：

```json
{
  "code": 1,
  "data": {},
  "msg": "success"
}
```

要求：

- `code`：成功为 `1`，失败为 `0` 或其他错误码
- `data`：返回体
- `msg`：提示文案

### 1.2 认证头

登录后前端会带：

```http
Authorization: Bearer <token>
```

### 1.3 路径前缀

前端项目的 `.env.development` / `.env.production` 中配置：

```env
VITE_APP_BASE_API = /api
```

因此，所有接口最终路径都带 `/api` 前缀。

## 三、字段对齐原则（必须遵守）

### 3.1 命名规则

- 数据库字段：`snake_case`
- Java 属性：`camelCase`
- 前端字段：页面绑定字段，通常是 `camelCase`

### 3.2 允许存在的转换

```text
real_name -> realName -> name
college_id -> collegeId -> collegeName
class_id -> classId -> className
```

这说明：

- 数据库可以保留 `real_name`
- `VO` 中可以返回 `realName`
- 前端页面最终直接使用 `name`

### 3.3 不能出现的情况

- 前端拿 `realName` 但后端返回 `name`
- 前端写 `pageSize`，后端却要求 `limit`
- 分页返回 `list`，前端却写 `records`
- 数据库字段直接暴露给前端而不经过 `VO` 映射

## 四、数据库与前端兼容原则

### 4.1 保持现有表结构优先

如果数据库已经存在表和字段，并且已写好功能，不要为了“字段更顺手”而强改表结构。

推荐顺序：

1. 先保证 `VO` 字段和前端一致；
2. 再在 `Service` 层处理映射；
3. 最后才判断数据库是否需要补充字段。

### 4.2 只在确实需要时加字段

仅当满足下面任一条件时，才考虑数据库调整：

- 前端强依赖这个字段，而当前表确实没有
- 查询逻辑需要它并且无法通过联表查询完成
- 该字段已经被业务强制使用，并且设计就是必需的

---

## 五、后端开发完成的标准

每个接口开发完成后，必须满足：

- [ ] URL 和前端 `src/api/*.js` 一致
- [ ] 请求参数名和前端调用一致
- [ ] 返回字段名和页面表单、表格绑定一致
- [ ] 分页返回结构统一
- [ ] 可直接在页面中显示，不需要前端再手工转换
- [ ] 已有数据库结构尽量不改动

---

## 六、结论

这份文档的核心意思只有一条：

前端真实需求决定后端字段和接口设计，后端不能“自创字段”和“自创返回结构”。

只要后端按照 `DTO -> Service -> VO -> Controller` 这条链路来设计，并且强调“VO 驱动前端字段”，就不会出现前后端字段不一致的问题。

## 十、后端接口对接建议

1. 所有 `api/*.js` 文件应统一调用 `src/utils/request.js`。
2. 统一返回结构必须保持一致：`{ code, data, msg }`。
3. 所有分页接口建议统一使用：

```json
{
  "page": 1,
  "limit": 20
}
```

4. 下载类接口建议使用 `responseType: 'blob'`。
5. 文件上传接口建议使用 `multipart/form-data`，并在后端明确解析 `file` 字段。
6. 建议统一命名规范：
   - 查询：`list`, `detail`, `stats`, `search`
   - 新增：`add`, `create`, `post`
   - 修改：`update`, `put`
   - 删除：`delete`, `remove`
